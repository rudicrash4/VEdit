# VEdit — General Design Document (GDD)

**Project:** VEdit  
**Platform:** Android  
**Audience:** Personal use; no commercial monetization planned  
**Product direction:** Hybrid mobile video editor  
**Document status:** Initial product specification  
**Repository:** https://github.com/rudicrash4/VEdit

---

## 1. Product Vision

VEdit is an Android-native video editing application inspired by the accessibility of CapCut and the deeper editing controls found in professional mobile editors.

The goal is to create a reliable, offline-first editor with a multi-track timeline and practical advanced tools such as speed ramping, keyframes, effects, and color adjustments.

VEdit must prioritize a dependable editing workflow over a large number of unfinished features. The preview and exported result should match as closely as the chosen Android media pipeline permits.

## 2. Product Principles

1. **Local-first:** Projects and imported media remain on the device unless the user explicitly exports or shares them.
2. **No account required:** No login, subscription, payment, advertising, or mandatory cloud service.
3. **No watermark:** Exports must not add a VEdit watermark.
4. **Real functionality:** Every visible control must work or be clearly marked as unavailable/not implemented.
5. **Non-destructive editing:** Editing operations should be represented as project data; do not modify original media files.
6. **Recoverability:** Autosave and project recovery are core requirements.
7. **Incremental delivery:** Build and test a working app after each development phase.
8. **Maintainability:** Keep timeline, project, preview, effects, audio, and export responsibilities separated.

## 3. Target Platform and UX

- Native Android application.
- Kotlin.
- Jetpack Compose for application UI, unless a documented technical reason requires a different approach for a specific component.
- Dark-first visual theme.
- Portrait phone layout as the primary target.
- Responsive layouts for different phone screen sizes.
- Offline operation after installation.

### 3.1 Hybrid Editor Layout

The editor combines a simple workflow with access to advanced controls.

**Main editor screen:**
- Top bar: back, project name, undo, redo, export.
- Preview area: video/image preview with playback controls.
- Timeline area: ruler, playhead, tracks, clips, thumbnails/waveforms where available.
- Bottom toolbar: context-sensitive editing actions.
- Properties panel: detailed settings for the selected clip, audio, text, or effect.

**Interaction requirements:**
- Horizontal timeline scrolling.
- Pinch-to-zoom timeline where practical.
- Select, move, trim, split, duplicate, and delete clips.
- Clear selected-item state.
- Touch targets suitable for phones.
- Avoid placing essential controls too close to screen edges.
- Timeline gestures must not conflict with vertical scrolling or preview gestures.

### 3.2 Contextual Editing

When the user selects a clip, show clip actions such as Split, Speed, Volume, Animation, Adjust, and Delete.

Advanced tools should open focused panels:
- Speed panel: normal speed and curve editor.
- Keyframe panel: keyframe navigation and parameter controls.
- Adjust panel: color and image adjustments.
- Audio panel: volume, fades, and audio controls.
- Text panel: text content and styling.

## 4. User Workflow

1. Create a project.
2. Choose project aspect ratio and frame rate.
3. Import video, image, and audio media using Android's supported document/media picker.
4. Add media to timeline tracks.
5. Arrange and edit clips.
6. Add text, audio, effects, and adjustments.
7. Preview the project.
8. Save automatically and manually.
9. Export to a video file.
10. Share or open the exported file using Android sharing intents.

## 5. Feature Scope

### 5.1 MVP — Required First Usable Version

The first usable release must include:

- Create, rename, open, and delete projects.
- Import video, image, and audio.
- Media permission/picker handling appropriate to supported Android versions.
- Video preview and playback controls.
- Timeline with at least a primary video track and separate audio track.
- Add, select, move, trim, split, duplicate, and delete clips.
- Basic clip ordering and timeline duration calculation.
- Basic text overlay.
- Basic audio volume and fade controls, if supported by the validated export path.
- Normal speed presets (at minimum 0.5x, 1x, and 2x, subject to media/API support).
- Project save and autosave.
- Export to MP4 using a supported codec/profile.
- Export progress, cancellation where supported, and clear error reporting.
- Debug APK generated by GitHub Actions.
- No watermark.

Do not claim multi-track compositing, speed ramping, or effects are complete unless they are reflected in the exported file and verified by tests.

### 5.2 Timeline and Clip Editing

Target capabilities:
- Multiple video/image tracks.
- Multiple audio tracks.
- Text/overlay tracks.
- Clip placement and duration.
- Trim start/end.
- Split at playhead.
- Move/reorder clips.
- Duplicate and delete.
- Track mute/visibility/lock where implemented.
- Timeline zoom and horizontal scroll.
- Accurate time ruler and playhead.
- Undo/redo for supported editing commands.

For MVP, implement a stable subset first; expand track count and advanced interactions in later phases.

### 5.3 Speed Controls and Speed Ramp

**Normal speed:**
- Provide useful presets such as 0.25x, 0.5x, 1x, 1.5x, 2x, and 4x when supported.
- Clearly show when a device/media combination cannot support a requested mode.

**Speed ramp:**
- Allow the user to define time/speed control points.
- Provide linear interpolation initially.
- Add smooth/ease or Bezier curve options only after the basic time mapping is correct.
- Include a curve visualization and editable control points.
- Support preview and export using the same speed mapping model.
- Define how audio behaves when speed changes (for example, pitch-preserving option only if supported; otherwise document pitch change).
- Handle clip duration recalculation and timeline synchronization.

Speed ramp is a high-priority advanced feature, but it must be implemented and validated as a real time-remapping feature, not as a UI-only graph.

### 5.4 Keyframes

Target animated properties:
- Position X/Y.
- Scale.
- Rotation.
- Opacity.
- Volume.
- Selected effect parameters where supported.

Interpolation:
- Linear first.
- Ease-in/ease-out and custom Bezier as later enhancements.

Keyframe data must be stored in the project and applied consistently in preview and export.

### 5.5 Text and Overlays

- Add and edit text.
- Font family selection from supported/local fonts.
- Size, color, alignment, outline, shadow, and background where implemented.
- Position, scale, rotation, and opacity.
- Text duration on timeline.
- Multiple text clips.
- Subtitle import (SRT) as a later enhancement.

### 5.6 Effects and Adjustments

Initial adjustments:
- Brightness/exposure.
- Contrast.
- Saturation.
- Temperature/tint where feasible.
- Sharpen and vignette only after quality/performance validation.

Potential later effects:
- Blur.
- Glow.
- Sharpen.
- Noise.
- Vignette.
- RGB split/chromatic aberration.
- Glitch.
- Shake.
- LUT import.
- Chroma key and masking.

Effects must have documented performance costs and must not silently degrade export quality.

### 5.7 Audio

- Import audio.
- Place audio clips on timeline.
- Trim, move, split, duplicate, delete.
- Volume control.
- Fade in/out.
- Multiple audio tracks as the architecture matures.
- Waveform display as a later enhancement.
- Audio extraction from video as a later enhancement.

### 5.8 Export

Initial export targets:
- MP4 container.
- H.264 where supported.
- 720p and 1080p output options where device capabilities permit.
- 24, 30, and 60 fps options only when supported by source and export pipeline.
- Configurable quality/bitrate presets.
- Export progress and completion state.
- Save through Android MediaStore or Storage Access Framework.
- No watermark.

Do not promise 4K, H.265, or 60 fps on every device. Expose only modes verified as supported. Preserve audio/video synchronization and correct orientation.

## 6. Project Management

- Project list with thumbnail, name, and last modified time.
- Create, rename, duplicate (optional), and delete.
- Autosave after meaningful edits, with debouncing to avoid excessive writes.
- Recovery from an interrupted session.
- Store project metadata and edit decisions separately from original media.
- Handle moved or unavailable source files gracefully.
- Provide a relink/replace-media workflow if feasible.

### 6.1 Project Data

Project data should include:
- Schema version.
- Project ID and name.
- Canvas dimensions/aspect ratio.
- Frame rate/timebase.
- Track definitions.
- Clip source references.
- Source in/out points.
- Timeline positions.
- Transform values.
- Speed curves.
- Keyframes.
- Audio settings.
- Text and effect parameters.
- Export preferences.

Use a versioned schema and migration strategy. Do not rely on absolute file paths alone; use Android URI/persistable access where appropriate.

## 7. Non-Functional Requirements

- Smooth timeline interaction on target mid-range Android devices.
- Avoid loading entire source videos into memory.
- Use thumbnails/proxies/cache where beneficial.
- Handle large files and low-storage conditions.
- Show meaningful error messages.
- Avoid data loss on process death or app restart.
- Keep UI responsive during import, thumbnail generation, and export.
- Respect Android lifecycle and scoped storage.
- Provide basic accessibility labels and readable contrast.
- Include crash-safe project persistence.

## 8. Development Phases

**Phase 0 — Repository and feasibility audit**
- Inspect the existing GitHub repository.
- Confirm project is empty or identify existing content; do not assume.
- Audit candidate libraries, licenses, maintenance status, Android compatibility, and API limitations.
- Build a minimal Android app through GitHub Actions.

**Phase 1 — Foundation**
- Gradle project, app shell, navigation, theme, project list.
- CI build and basic unit tests.

**Phase 2 — Media**
- Import video/image/audio.
- Media metadata and thumbnail generation.
- Preview playback.

**Phase 3 — Project and timeline**
- Versioned project model.
- Tracks and clips.
- Timeline UI and basic operations.
- Autosave and restore.

**Phase 4 — Basic editing and export**
- Trim, split, move, delete, text/audio basics.
- First real MP4 export.
- Verify preview/export consistency.

**Phase 5 — Speed and keyframes**
- Normal speed.
- Speed curve/time mapping.
- Keyframe model and interpolation.
- Preview and export tests.

**Phase 6 — Effects and color**
- Basic adjustments.
- Effect pipeline.
- Performance tests.

**Phase 7 — Hardening**
- Device compatibility.
- Memory/performance.
- Error handling.
- Regression tests.
- Release workflow.

A phase is complete only when its acceptance criteria pass and the app can be built by CI.

## 9. MVP Acceptance Criteria

The MVP is accepted only if:
1. The app installs and launches on a real Android device.
2. A user can create and reopen a project.
3. Video can be imported and previewed.
4. At least basic clip operations work on the timeline.
5. The project survives app restart.
6. A real MP4 export is produced and can be played by another player.
7. Exported output reflects the implemented edits.
8. GitHub Actions produces a downloadable APK artifact.
9. CI tests pass.
10. No watermark, login, payment, or network account is required.

## 10. Out of Scope for Initial MVP

- Cloud accounts and synchronization.
- Collaboration.
- Social network publishing APIs.
- AI cloud features.
- Subscription/payment.
- Advertising.
- Desktop version.
- Guaranteed support for every codec/device.
- Guaranteed professional-grade performance on all phones.

## 11. Product Decision Log

- Platform: Android Native.
- Language: Kotlin.
- UI: Jetpack Compose.
- Design: Hybrid editor UI.
- Architecture: Custom editor/project/timeline systems using audited open-source media components.
- Target: Mid-level editor, with advanced features added iteratively.
- Distribution: Personal use.
- Monetization: None.
- Watermark: None.
- Operation: Offline-first.
- Source repository: `https://github.com/rudicrash4/VEdit`.
- Build system: GitHub Actions.
